- Campaign capabilities and readiness derive only from src/lib/campaign.ts; sensitive DEMO RPCs use server wrappers and service-only dispatcher to prevent direct API bypass. LIVE services require separate verified implementations, never reuse DEMO records as paid gifts. Emails/bookings remain simulations only where capabilities permit.
- Cash gifts: create_cash_request stores only the SHA-256 of a server-generated one-time 16-char code (2h expiry); volunteers look up/confirm through security-definer RPCs via staff roles or the shared-password session (see src/lib/AGENTS.md), and confirm_cash_request locks the row so a second scan returns the same ornament instead of a duplicate. /volontari is unlinked but protected by that server session, not by obscurity; only host volontari.natale.crimonza.org redirects / to /volontari (src/start.ts). Signed-out visitors get a presentation mode backed by the in-memory sandbox in src/lib/volunteer-demo.ts (same flows, zero Cloud calls) so it can be shown without accounts. Santa booking data stays in component state (src/lib/santa.ts); postcards are drawn on a local canvas and shared, never uploaded.

- Shared demo tree lives in Lovable Cloud table demo_ornaments; visitors write/read only via security-definer RPCs (hang_ornament, public_tree, my_ornaments), moderators (user_roles admin/moderator) read/update via RLS — keeps private dedicas and counts tamper-proof.
- Mobile and TV share a lazy client-only React Three Fiber scene; ornament slots come from creation order (R2 low-discrepancy best-candidate sampling with a 3D clearance ellipsoid, sized for the count at arrival) and are projected onto the shared canopy profile in src/lib/tree-layout.ts, so baubles never touch, rest on the needles and keep their place as the tree grows wider and taller.
- The tree is one procedural indexed canopy (stacked scalloped skirts) plus instanced tufts, light strings and baubles whose project motifs are painted on canvas textures; everything is instanced with bounded pixel ratio so each growth stage stays complete within mobile GPU budgets.
- Casetta events live in Cloud table casetta_events: anon reads only visible+confirmed+upcoming rows via RLS, moderators manage them from /moderazione; the TV lists only those rows and shows a generic casetta invitation when none qualify, so no appointment is ever invented.
- /albero-live uses public-only bounded/abortable polling, a six-arrival queue and one cleanup-owned Wake Lock/reload controller with noon protection; last-good data and illustrated fallback survive outages. Brand, counter and QR stay outside rotating scenes; device uptime is not guaranteed.
- Unlinked /tv-preview: TreeTV `preview` beats (no loop/wake lock/reload) and ?modo=crescita, which feeds the real TreeStage in-memory ornaments in simulated TV/phone screens, so screenshots use real components without touching /albero-live or the shared tree.
- The TV wish wall is the one full-frame scene: src/lib/tv-wall.ts packs approved wishes (plus labelled examples while few) onto 3–5 twine rows in cqw, with conservative height estimates, line-clamp and bottom rows kept clear of the always-visible QR block, so notes never overlap at any 16:9 size.
- The dedication panel uses a same-URL history entry for Back dismissal plus visible close/outside/Escape controls, so opening a gift never traps navigation.
- CriMark/CriLockup embed the official image files untouched; CriLockup adds the territorial line in Arial per CRI manual §1.3 using geometry measured in src/lib/cri-lockup.ts (email uses the HTML twin lockupHtml), so the mark is never redrawn and the composition can be swapped for an official lockup file.
- Tree rendering goes through TreeStage: WebGL is detected before the 3D chunk loads, and missing WebGL, scene errors or context loss fall back to the illustrated Tree with the same shared ornaments, so no browser shows an empty stage.
- Gift amounts are validated by one shared schema (cash.ts amountSchema) and again inside every security-definer RPC that records a gift, so UI bypasses cannot store invalid amounts.
- Post-action confirmations are inline (no full-screen overlays) and the router shows a pending view plus reloads on chunk-load failure, so the previous page never stays on screen under a new URL.
- Kids' mission feedback is rendered only through Kit Bubble/HelperLine inside HelperProvider, so the guide picked in the hub (device-local, no personal data) speaks every hint consistently across missions.
- Casetta poster and product photos are nullable slots in src/lib/casetta.ts (CASETTA_MEDIA); CasettaPoster/CasettaPhoto show the official file untouched when a slot is filled, a sober placeholder on /casetta otherwise, and nothing on home/TV, so originals are never recreated and filling a slot updates every surface.
- Kindness calendar: kindness_doors holds 24 staff-editable texts; the public reads them only through kindness_calendar(), which unlocks by the server date in Europe/Rome and returns null text for locked doors, so client clocks cannot peek ahead. The public calendar unlocks at midnight; the TV plays its once-a-day noon ceremony (CEREMONY_HOUR in src/lib/kindness.ts) only when running across that boundary, so reloads never replay it. Plaque positions live in src/lib/advent-layout.ts as fractions of the untouched sede illustration, so HTML doors stay aligned at any size.
- Wishes: volunteers mint one-time 16-char codes (only the SHA-256 is stored, 7-day expiry, rate-limited) via create_wish_token; submit_wish row-locks and consumes the code, every wish starts pending, only is_moderator() can moderate, and public_wishes() returns approved+consented rows only, so pending/rejected text never reaches the wall or TV. Signed-out demo flows use createDemoWishApi (in-memory, zero Cloud writes).
- The Santa chimney scene (SantaChimney.tsx) is time-driven: AutoSantaScene starts once via IntersectionObserver (home = short landing teaser, /babbo-natale = full story with replay) and shows a static frame under reduced motion, so it never depends on scroll position or blocks scrolling.
- ONLINE_GIFT restores digital calendar/academy through experience flags and renders a separate informational casetta variant using the shared product catalog; FULL branches and date/provider logic remain unchanged to keep restoration narrowly scoped.
